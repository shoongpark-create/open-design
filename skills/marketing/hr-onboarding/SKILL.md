# 패션 신입 온보딩 스킬

K-패션 브랜드의 **디자이너·MD 신입 온보딩 가이드**를 단일 HTML 파일로 생성합니다. 신입의 입사 첫날부터 90일까지의 일정·마일스톤·리소스를 한 페이지에 압축한 **사내 가이드 문서**입니다.

이 산출물의 청중은 **신입 본인 + 직속 디렉터 + 온보딩 버디 + HR 담당자**입니다. 한국 패션기업에서는 브랜드 디렉터/디자인실장 또는 MD실장이 직접 작성하며, 30/60/90일 플랜은 매 시즌 사이클 기준(예: 6월 입사 → 9월 28FW 컨셉 보드 참여)으로 설계합니다.

K-패션 브랜드 컬처는 SaaS 회사와 다릅니다. 입사 첫 주에 **OEM 공장 견학, 라인업 시트 투어, 견본 컨퍼 참관, 품평회 참관**이 들어가야 하며, 마일스톤은 코드 PR이 아니라 **컨셉 보드 제출 → 라인업 기획 참여 → 첫 발주 컨펌 사인** 같은 시즌 산출물 단위로 설계합니다.

## 환경 호환성

이 스킬은 모든 LLM 환경에서 동일하게 사용할 수 있습니다.

- **Claude 환경(Claude.ai · Claude Code)**: 결과물을 `<artifact>` 태그로 감싸 출력합니다.
- **그 외 환경(ChatGPT · Gemini · Grok · 일반 채팅)**: 표준 HTML 코드 블록으로 출력합니다.
- **OpenDesign 환경**: frontmatter의 `od:` 블록과 `data-od-id` 속성으로 인라인 코멘트 사용 가능. 다른 환경에서는 일반 `id`로 대체합니다.

본문 작업 흐름은 모든 LLM이 자력으로 따라할 수 있도록 명시적으로 작성되어 있습니다.

## 출력 언어 정책

K-패션 신입 가이드의 등록(register)을 따릅니다.

- 직무명은 한국 패션 표준: **디자이너**(디자인실), **MD**(머천다이저, 영업기획), **PD**(생산 담당), **RMD**(리테일 머천다이저), **VMD**(비주얼 머천다이저), **에디터**(브랜드 콘텐츠), **마케터**(IMC).
- 조직 호칭 유지: 디자인실장, MD실장, 브랜드 디렉터, 대표, 영업기획팀, 마케팅실, 이커머스팀, 채널영업팀.
- 시즌 산출물 용어 유지: 컨셉 보드, 컬러 스토리, 패브릭 보드, 라인업 시트, 그래픽 디렉션, 룩북, 키 아이템 시트, 액세서리 라인업, 핏 시스템, 품평회, CON(컨퍼), LOCK.
- 호칭은 직무명 + 이름 (예: "디자인실장 김도하", "온보딩 버디 박지연 디자이너").
- 본문은 명사구·문장형 혼용 — 친근하되 사무적 톤. "오신 것을 환영합니다", "함께해주세요", "참여 권장" 같은 한국 사내 등록.
- 30/60/90일 마일스톤은 **시즌 산출물 단위**로 작성. "첫 PR 제출" → "첫 컨셉 보드 발표".

## 폴더 구조

```
hr-onboarding/
├── SKILL.md       ← 이 파일
└── example.html   ← 작성 예시 (와키윌리 우먼 라인 디자이너 신입 온보딩)
```

## 작업 흐름

### Step 0 — 사전 점검

1. `example.html`을 처음부터 끝까지 읽어 커버 + 1일차 시간표 + 1주차 + 30/60/90 마일스톤 + 리소스 + 체크리스트 구조를 파악하세요.
2. 프로젝트 루트의 `DESIGN.md`(또는 등가 디자인 토큰 파일)를 읽고 색상·타이포 토큰을 `:root` CSS 변수로 바인딩하세요. 친근한 브랜드 톤이면 세리프 디스플레이(예: Hahmlet, Grandiflora One) 권장.

### Step 1 — 정보 수집

다음 항목이 빠져 있으면 첫 발견 폼에서 함께 물어보세요.

- **신입 정보**: 이름, 직무(디자이너/MD/PD/마케터 등), 담당 라인(UNI/WOMEN/액세서리/슈즈), 입사일
- **온보딩 라인**: 직속 디렉터(디자인실장/MD실장), 온보딩 버디(시니어 동료)
- **시즌 사이클 위치**: 입사 시점이 어느 시즌 사이클인지 (예: 6월 입사 → 28SS 컨셉 기획 시작 시점)
- **30/60/90일 목표**: 각 시점의 마일스톤 3개씩 (시즌 산출물 단위)
- **브랜드 컬처 특징**: 마뗑킴 친근 SNS 톤 / 아더에러 글로벌 신비감 / 와키윌리 캐릭터 IP 팬덤 / 마르디 메크르디 셀럽 친화 등 — 컬처 한 문장 인용

### Step 2 — 레이아웃 순서

1. **커버 배너** — 이름 placeholder, 직무, 입사일, 담당 디렉터, 온보딩 버디, 환영 문구 1줄(브랜드 톤 반영)
2. **1일차 시간표** — 09:00~17:00 사이 7~8개 슬롯. K-패션 1일차 표준: 디렉터 킥오프 / IT 셋업 / 라인업 시트 투어 / 팀 점심 / 핸드북 읽기 / "내가 왔다" 사인(노션·인스타·내부 SNS 등록) / EOD 체크인
3. **1주차 타임라인** — 월~금, 하루 2개 활동. 디자인 시스템 투어, 첫 품평회 참관, OEM 공장 1회 견학 또는 견본 컨퍼 참관, 시니어 디자이너 그림자 등
4. **30/60/90일 마일스톤** — 카드 3개, 각 3개 성과 (시즌 산출물 단위)
5. **북마크 리소스** — 브랜드 가이드라인, 시즌 라인업 노션, 피그마/스케치 디자인 시스템, 시즌 대시보드, ERP 입문, 슬랙 채널
6. **"준비 완료 신호" 체크리스트** — 5개 항목. 시스템 셋업 / 라인 동료 미팅 / 첫 산출물 제출 / 회의 흐름 파악 / 질문 편안함

### Step 3 — 작성

1. 단일 HTML 문서(`<!doctype html>` ~ `</html>`)로 작성, CSS는 인라인 `<style>` 한 블록.
2. 시맨틱 HTML: `<header class="cover">`, `<section>`, `<footer>`.
3. 모든 색상은 `:root` CSS 변수로 바인딩.
4. 친근한 톤: 세리프 디스플레이 + 둥근 코너 + 따뜻한 베이지/오프화이트 배경 권장.
5. 일정의 시간 표기는 24시간제(09:00, 14:00 등) — K-패션 사내 표준.

### Step 4 — 자체 검수

- 1주차 활동 중 최소 1개는 **현장 활동** (공장 견학, 견본 컨퍼, 품평회, 매장 라운드 등)
- 30/60/90일 마일스톤은 **코드/PR이 아니라 시즌 산출물 단위** (컨셉 보드, 라인업, 컬러 락, 핏 컨펌, 룩북 참여 등)
- 리소스는 K-패션 표준 도구 포함: 노션, 피그마, 카페24/쇼피파이 어드민, 무신사 파트너센터, ERP
- 브랜드 컬처 한 문장이 커버 또는 헤더에 인용됨
- 호칭은 직무명 + 이름 (예: "디자인실장 김도하")

## 한국 K-패션 브랜드 컬처 (참고)

온보딩 가이드 작성 시 참고할 브랜드 컬처 패턴.

| 브랜드 | 컬처 톤 | 신입에게 강조하는 키워드 |
|---|---|---|
| **마뗑킴** | 친근한 SNS 톤, 대표 직접 소통 | 인스타 톤·앱 알림톡 가독성·미니멀 시크 |
| **마르디 메크르디** | 셀럽 친화, 프렌치 감성 | 화훼 모티프·셀럽 매칭·매거진형 화보 |
| **아더에러** | 글로벌 신비감, 컨셉추얼 | 실험·왜곡·블루 키컬러·익명성 |
| **키르시** | 영컬처, 발랄한 비비드 | 비비드 컬러·체리 심볼·MZ 친화 |
| **와키윌리** | 캐릭터 IP, 팬덤 친화 | 캐릭터 그래픽·K-아이돌 매칭·재미 |
| **무신사 스탠다드** | 데일리 베이직, 신뢰감 | 한국적 핏·가성비·표준화 |
| **앤더슨벨** | 모던 컨템포러리, 글로벌 | 시즌 컬렉션·해외 PR·미니멀 디테일 |
| **준지** | 하이엔드 컨템포러리, 건축적 | 실루엣·테일러링·소재 깊이 |

위 사례는 카피 참고용. 실제 가이드는 사용자 브랜드 실데이터로 작성.

## 한국 패션기업 조직 R&R 메모

온보딩 가이드 작성·검토 흐름.

- **브랜드 디렉터 / 디자인실장 / MD실장**: 가이드 작성 주체, 30/60/90 마일스톤 결정
- **온보딩 버디 (시니어 동료)**: 1주차 활동 동행, 미세 컬처 전달
- **HR 담당자**: 시스템·복지·계약 셋업 (1일차 IT 셋업 슬롯)
- **마케팅실**: 브랜드 컬처 문장·SNS 채널 안내
- **이커머스팀**: 자사몰/입점채널 백오피스 접근권한 발급
- **VMD**: 매장 라운드 일정 안내 (디자이너·MD 신입은 입사 2~4주차 매장 라운드 권장)

## 시즌 사이클 내 위치

신입 온보딩은 **연중 발생**하지만, 30/60/90일 마일스톤은 **현재 시즌 사이클의 어느 산출물에 합류시킬지** 기준으로 설계합니다.

```
[예시: 6월 1일 입사 (디자이너 · 28FW 컨셉 단계)]
    ↓
[30일 · 7월] 첫 컨셉 보드 코멘트 제출 → fashion-concept-board 참여
    ↓
[60일 · 8월] 라인업 1건 담당 → fashion-new-lineup 참여
    ↓
[90일 · 9월] 첫 키 아이템 디자인 → fashion-key-item-sheet 발표
```

```
[예시: 1월 입사 (MD · 27SS 본생산 단계)]
    ↓
[30일 · 2월] 1차 발주 시트 검토 보조 → invoice 산출물 보조
    ↓
[60일 · 3월] 견본 CON 참관 → 견본 그레이딩 코멘트
    ↓
[90일 · 4월] 첫 시즌 결산 보조 → finance-report 데이터 보조
```

## 채널 연계

온보딩 가이드는 다음 시스템과 연동됩니다.

- **노션** — 신입 워크스페이스, 시즌 보드 접근권한
- **슬랙** — `#디자인-팀`, `#md-room`, `#27ss-launch` 등 시즌 채널
- **피그마 / 스케치** — 디자인 시스템 라이브러리
- **ERP / 발주 시스템** — 자체 ERP, 자라남, 이지어드민
- **무신사 파트너센터 / 29CM 파트너** — 입점 채널 백오피스
- **카페24 / 쇼피파이 / 메이크샵** — 자사몰 어드민
- **구글 워크스페이스 / MS365** — 시즌 시트, 라인업 표

## 출력 규약

단일 HTML 문서(`<!doctype html>`부터 `</html>`까지)를 결과물로 출력하세요.

- **Claude 환경(Claude.ai · Claude Code)**: 결과물을 아래와 같이 `<artifact>` 태그로 감싸세요.
  ```
  <artifact identifier="onboarding-slug" type="text/html" title="온보딩 가이드 제목">
  <!doctype html>
  <html>...</html>
  </artifact>
  ```
- **그 외 환경(ChatGPT · Gemini · Grok · 일반 채팅)**: 표준 마크다운 HTML 코드 블록으로 출력하세요.
  ````
  ```html
  <!doctype html>
  <html>...</html>
  ```
  ````

출력 앞에 한 문장 요약(예: "와키윌리 신입 디자이너 서연의 30/60/90일 온보딩 가이드를 작성했습니다.")을, 뒤에는 아무것도 덧붙이지 마세요.
