# K-패션 발주·생산 운영 매뉴얼(런북) 자체 검수 체크리스트

산출물 출력 직전에 한 항목씩 직접 확인하세요. **P0**는 통과 필수, **P1**은 강력 권장, **P2**는 다듬기.

## P0 — 통과 필수

- [ ] 헤더에 브랜드/시즌/차수 크럼 + H1 + 부서(`@생산-N팀` 또는 `@MD-N팀`) + 버전 + Tier 배지 모두 표기
- [ ] **01. 발주 개요** 패널이 채워짐 — 발주 규모(SKU·PCS·사입금액·억) + 입고 마감일 + 지연 시 매출 영향
- [ ] **의존성 리스트**에 **최소 4종** 포함 — 원단 / 부자재 / OEM 공장 / QC 외주실 / 3PL 물류 중 4개 이상
- [ ] 각 의존성 항목에 현재 상태 (`정상` / `납기 지연 N일` / `결품` / `컨택 중`)
- [ ] **02. 알람 표** 최소 4행 이상. 각 행에 알람 코드(`code` 폰트) + 심각도 배지(SEV-1/2/3) + 의미 + 1차 대응
- [ ] 알람 표에 **SEV-1 최소 1건**(라인 전체 정지급) + SEV-2 다수 + SEV-3 1건 (각 심각도 사용 확인)
- [ ] **03. 표준 절차 3~4건**. 각 절차에 명령어 블록(`<pre>`) + 한국어 주석(`# ...`) + K-패션 변수
- [ ] 명령어 변수에 **K-패션 코드** — 시즌(`27SS`) / P/O 번호(`PO-27SS-W001`) / LOT(`LOT-27SS-W023`) / 공장 코드(`OEM-A`)
- [ ] **04. 담당자 로테이션 표** 최소 4주차 분량. PD / RMD / QC 3 컬럼 모두 채워짐
- [ ] **05. 사고 대응 체크리스트 5단계** — 알람 확인 → 채널 개설 → 상태 스냅샷 → 우선 대응 → 인수인계
- [ ] 모든 색상은 `:root` 토큰에서 옴 — 임의 hex 금지
- [ ] 통화 단위는 원/만원/억 (USD 금지). 수량은 PCS/장/마 (yard 금지)

## P1 — 강력 권장

- [ ] 본문 폰트 `Pretendard Variable`, 디스플레이는 `--font-display-report`, 명령어 블록은 mono
- [ ] 절차 블록의 명령어 어휘가 K-패션 운영 동사 — `po submit` / `color relock` / `claim open` / `inbound check` / `qr simulate` (`kubectl`·`docker` 같은 SaaS 어휘 금지)
- [ ] 알람 표 1차 대응은 한국 패션 운영 등록 명사구 — "공장에 재염색 요청", "재단 재검 지시"
- [ ] 사고 대응 5단계 중 4번째 단계가 **진단보다 우선 대응** 원칙 명시 — "본생산 정지는 최후의 카드"
- [ ] 시즌 표기 `27SS` / `26FW` / `S1 판기` 일관성
- [ ] 사입금액·차감액 같은 금액 표기 만원/억 단위, 천 단위 콤마

## P2 — 다듬기

- [ ] 헤더 우측 Tier 배지 (`Tier 0` 시즌 메인 / `Tier 1` SPOT / `Tier 2` 캐리오버) 정합
- [ ] 명령어 블록의 `cmt` / `var` / `ok` span 컬러 구분 적용 (주석 grey / 변수 yellow / 성공 green)
- [ ] 로테이션 표 4주차에 견본 CON → 본생산 → 입고 검수 사이클 정합성
- [ ] 사고 대응 단계 카드의 `<code>` 인라인 사용 (`/ack`, `/incident open`, `/incident close`)
- [ ] 모바일 880px 폭에서 `.summary` / `.checklist` 1열 폴백 작동
- [ ] 푸터에 작성 부서 + 매뉴얼 버전 + 소스 파일 경로 (예: `생산-매뉴얼/27ss-po1.md`)

## 하드 룰 위반 점검 (anti-pattern)

- [ ] 의존성에 SaaS 인프라(AWS / k8s / Docker) 등장 → K-패션 운영 의존성(공장 / 부자재 / QC / 3PL)으로 교체
- [ ] 알람 코드가 영문만 (`high_cpu`) → K-패션 운영 코드(`color.deltaE`, `qc.defect_rate`)로 교체
- [ ] 명령어가 일반 셸(`bash`, `kubectl`, `npm`) → K-패션 운영 동사(`po submit`, `qr simulate`)로 교체
- [ ] SEV-1 알람 0개 → 최소 1개 (라인 전체 정지급 — 원단 결품 / 봉제 결함 5%+)
- [ ] 절차 블록 0~2개 → 최소 3건 표준 절차 (발주·컬러락 변경·클레임·검수 중 3개)

## K-패션 특화 검수 (선택)

- [ ] OEM 공장 명칭이 K-패션 자연 — 합천 / 진주 / 대구 / 안양 / 의정부 + 중국 옌타이·다롄 (해외 OEM)
- [ ] 원단 거래처 — 대구 인견 / 부산 데님 / 동대문 종합 시장
- [ ] 3PL 표기 — 굿스플로 / 두손컴퍼니 / CJ대한통운 (Amazon FBA 금지)
- [ ] QC 외주실 위치 — 동대문 / 평택 / 김포 등
- [ ] 사고 채널 — 슬랙 `#생산-27ss` / 카카오 단톡방 / 위챗(중국 공장 동시 운영 시)
- [ ] 시즌 사이클 정합성 — 시즌 시작 3개월 전 1차 발주, 1.5개월 전 본생산, 1개월 전 입고 검수
